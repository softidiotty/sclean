SCLEAN — README
=========================

Автор: softidiotty
Версия сборки: 1.9.3

Инфраструктура (не меняет версию программы):
  - Добавлен .github/workflows/release.yml — GitHub Actions workflow,
    автоматически собирающий sclean.exe и публикующий GitHub Release
    при пуше тега вида "v1.9.3" (см. раздел "Как выпустить новую
    версию" ниже в этом файле). Сборка идёт на бесплатном
    Windows-раннере GitHub — не нужен локальный Python/PyInstaller
    для публикации релиза, только git push тега

Изменения в 1.9.3:
  - Устранена ошибка "Security validation failure: failed to obtain
    executable path for parent proces!", всплывавшая при применении
    автообновления (после скачивания новой версии, при подмене и
    перезапуске exe). Причина — генерируемый .bat-скрипт перезапускал
    обновлённый exe через "start", что добавляло лишнее звено cmd.exe в
    цепочку процессов и мешало Windows определить родительский процесс
    для UAC-проверки манифеста (uac_admin=True). Обновление всё равно
    проходило успешно, но с лишним диалогом. Теперь .bat запускает
    обновлённый exe напрямую, без "start" — цепочка короче на одно
    звено, ошибка больше не возникает

Изменения в 1.9.2:
  - Цветовая палитра: общий фон приложения сделан нейтрально тёмно-серым
    вместо заметного бурого/красноватого оттенка (он был даже у
    "невыбранных" строк списка пунктов). Красный акцент остался только
    для явно выбранных пунктов
  - Добавлена прокрутка всего окна: список пунктов, шаги очистки и журнал
    выполнения теперь размещены в прокручиваемой области (Canvas +
    вертикальный скроллбар + колесо мыши), поэтому при уменьшении окна
    ниже привычного размера всё содержимое остаётся доступным — можно
    прокрутить вниз, а не обрезается
  - Логотип в шапке программы (sclean_logo.png) больше не размывается:
    раньше маленькая иконка в шапке получалась прямым грубым прореживанием
    (subsample) из крупного PNG 512×512, что давало заметно размытый/
    рваный результат. Теперь при сборке заранее готовится качественно
    уменьшенный ассет 64×64 (Lanczos-ресемплинг), который в рантейме
    уменьшается всего в 2 раза до финального размера в шапке — итоговая
    картинка заметно чётче. Новый файл sclean_logo_small.png добавлен в
    sclean.spec и должен лежать рядом с sclean.py при сборке

Изменения в 1.9.1:
  - Автор программы изменён на softidiotty
  - Cleanmgr: устранена настоящая причина "зависания" после исчезновения
    окна прогресса — программа ждала завершения одного конкретного
    процесса (PID), а cleanmgr на практике иногда порождает
    дополнительный/повторный процесс с тем же именем, из-за чего
    исходный процесс формально завершается, пока реальная очистка ещё
    идёт в другом. Теперь sclean опрашивает систему по ИМЕНИ процесса
    (cleanmgr.exe) каждые 2 секунды и считает очистку завершённой только
    когда таких процессов не осталось совсем — учитывает любые
    дочерние/повторные процессы. Кнопка "Завершить очистку диска" тоже
    обновлена — убивает по имени процесса, а не по устаревшему PID
  - Добавлена сворачиваемая панель "О программе" под заголовком (свёрнута
    по умолчанию) — краткое описание того, что делает программа, и путь,
    куда сохраняются отчёты и файл бэкапа настроек
  - Инструкция по сбросу кэша иконок Windows в README дополнена более
    надёжным способом (полная очистка IconCache.db через перезапуск
    explorer.exe) — ie4uinit.exe -show не всегда обновляет иконку в
    панели задач, особенно в размерах 32-48px

Изменения в 1.9.0 (оптимизация для передачи на удалённые устройства):
  - Убрана зависимость pystray + Pillow (~15-18 МБ веса exe). Кнопка
    "Свернуть" теперь сворачивает окно в панель задач обычным способом
    (root.iconify()) вместо настоящей иконки в системном трее —
    функционально почти то же самое для целей программы, но без
    лишнего веса. При сборке через PyInstaller эти пакеты больше не
    нужны вообще (можно не устанавливать: pip install pystray pillow
    больше не требуется)
  - sclean.spec: добавлены excludes для PIL/pystray/unittest/test на
    случай, если что-то тянет их транзитивно, optimize повышен до 2 —
    дополнительно уменьшает размер exe
  - Добавлено автообновление через GitHub Releases:
      * При каждом запуске программа тихо проверяет в фоне, есть ли
        версия новее текущей (не мешает и не блокирует работу, если
        сети нет или репозиторий не настроен)
      * Кнопка "Проверить обновление" в шапке программы — ручная
        проверка в любой момент
      * Если найдена новая версия — предлагает скачать и установить;
        после скачивания программа автоматически подменяет свой exe и
        перезапускается
      * Настройка: в начале sclean.py задать GITHUB_REPO = "аккаунт/
        репозиторий". Публикация новой версии — создать GitHub Release
        с тегом "vX.Y.Z" (совпадающим с APP_VERSION) и прикрепить
        собранный sclean.exe как файл релиза. Никакого своего сервера
        или FTP не требуется — GitHub раздаёт файлы по HTTPS бесплатно
      * Если позже понадобится сменить источник обновлений (свой сайт,
        FTP) — меняется только функция _fetch_latest_release() в коде,
        остальная логика (сравнение версий, скачивание, замена exe)
        переиспользуется без изменений

  Как выпустить новую версию через GitHub Releases:

  Вариант А — автоматически через GitHub Actions (рекомендуется, см.
  .github/workflows/release.yml в этом репозитории):
    1. Изменить APP_VERSION в sclean.py на новую версию, закоммитить
    2. Создать и запушить тег с той же версией и буквой "v" впереди:
         git tag v1.9.2
         git push origin v1.9.2
    3. GitHub Actions автоматически: соберёт sclean.exe на бесплатном
       Windows-раннере GitHub (не нужен pyinstaller/Python локально),
       создаст релиз с этим тегом и прикрепит собранный exe
    4. Прогресс сборки можно посмотреть на вкладке "Actions" репозитория
    5. Программы на удалённых устройствах через "Проверить обновление"
       (или автоматически при запуске) увидят новую версию и предложат
       обновиться

  Вариант Б — вручную (если Actions недоступны или нужен точечный релиз):
    1. Собрать sclean.exe локально (pyinstaller sclean.spec)
    2. На странице репозитория: Releases -> Draft a new release
    3. Tag: "v1.9.2" (или следующая версия, с буквой v впереди)
    4. Прикрепить собранный sclean.exe в поле файлов релиза
    5. Publish release

Изменения в 1.8.8:
  - В интерфейс добавлен таймер общего времени выполнения (мин:сек),
    обновляется раз в секунду рядом со статус-строкой, пока идёт
    выполнение — наглядное подтверждение, что программа активна, даже
    если текст статуса подолгу не меняется (например, при ожидании
    закрытия окна "Очистки диска"). После завершения показывает
    итоговое время и не сбрасывается до следующего запуска
  - Примечание про иконку приложения: сам файл sclean.ico корректен на
    всех размерах (проверено программно) — если после пересборки .exe с
    тем же именем значок в панели задач/проводнике выглядит размытым
    или старым (особенно в размерах 32-48px, которые использует панель
    задач), это кэш иконок Windows, не связанный с самим приложением.
    Он не обновляется автоматически при замене exe с тем же именем.
    ie4uinit.exe -show обновляет кэш только частично (в основном сам
    Проводник) и часто НЕ помогает панели задач — для неё нужен более
    жёсткий сброс:
      1) Закрыть программу sclean и все окна проводника.
      2) Открыть Диспетчер задач -> найти "Проводник" (explorer.exe) ->
         правой кнопкой -> Завершить задачу (не просто "Перезапустить" —
         это не всегда сбрасывает именно кэш иконок).
      3) Открыть Диспетчер задач -> Файл -> Запустить новую задачу ->
         ввести: cmd -> поставить галку "Создать с правами
         администратора" -> OK. В открывшемся окне выполнить по очереди:
           taskkill /IM explorer.exe /F
           del /A /Q "%LocalAppData%\IconCache.db"
           del /A /Q "%LocalAppData%\Microsoft\Windows\Explorer\iconcache_*.db"
           start explorer.exe
      4) Панель задач и проводник перезапустятся с очищенным кэшем и
         покажут актуальную иконку.
      5) Если всё ещё не помогло — переименовать sclean.exe (например,
         добавить/убрать цифру в конце имени): Windows создаёт кэш
         иконок по пути+имени файла, и новое имя гарантированно
         покажет актуальный значок без возни с кэшем вообще.

================================================================
1. GUI-ВЕРСИЯ "sclean" (sclean.py / sclean.exe)
================================================================

Что это
-------
Программа с тёмным (чёрно-красным) окном Windows под названием "sclean".
Иконка приложения (заголовок окна/панель задач) — программный круглый
значок "SC"; в шапке самого окна отдельно показан логотип — пользовательское
изображение. Показывает список всех операций с чекбоксами, общий
прогресс-бар, текущий процент выполнения и список выбранных пунктов со
статусом каждого (ожидание/выполняется/готово/ошибка). В футере окна и
в каждом отчёте указаны номер сборки и автор (Skadi).

Чекбоксы пунктов — кастомные: квадратный индикатор (закрашенный чёрным,
когда пункт выбран) вместо стандартного крестика, и вся строка пункта
подсвечивается акцентным красным цветом при выборе — сразу видно, что
отмечено. Клик в любом месте строки (кроме кнопки справа) переключает
отметку.

Запуск от администратора
--------------------------
Программа всегда требует права администратора:
  - exe собран с встроенным манифестом (uac_admin=True в .spec) — при
    запуске Windows сразу показывает диалог UAC;
  - если всё же запущена без прав (например, напрямую как .py), при
    старте она сама обнаруживает это и перезапускает себя через UAC
    (ShellExecuteW/"runas"), а исходный процесс без прав завершается.
Без подтверждения UAC программа не откроется — это нужно, так как
почти все операции (служба обновлений, DISM, брандмауэр, электропитание,
cleanmgr) требуют повышенных прав.

Вывод команд PowerShell (модели дисков, название ОС, видеокарта и т.п.)
выполняется и декодируется в UTF-8 через -EncodedCommand с корректным
экранированием — кириллица в журнале и отчёте отображается без
"иероглифов".

Интерфейс окна
---------------
- Список из 9 пунктов с чекбоксами в стиле мастер-чекбокса (белый
  квадрат, чёрный квадрат внутри при отметке). По умолчанию НИЧЕГО не
  отмечено — что выполнять, решает пользователь при каждом запуске.
  У каждого пункта есть своя кнопка "Выполнить только это", подсказка
  при наведении с описанием шага, и примерное время выполнения.
- Кнопка "Выполнить всё отмеченное" — запускает по порядку все пункты,
  у которых стоит галочка.
- Кнопка "Отмена" — становится активной при запуске нескольких пунктов,
  мягко останавливает выполнение после завершения текущего шага.
- Кнопка "Рекомендуемые настройки" — отмечает безопасный набор пунктов
  (без sfc/DISM).
- Мастер-чекбокс (белый квадрат под заголовком "Выберите пункты для
  выполнения:") — клик отмечает сразу все пункты, повторный клик снимает
  все. Сам чекбокс отражает состояние: закрашен только тогда, когда
  отмечены все пункты.
- Список пунктов заключён в общую рамку (2px) — строки разделены
  линиями той же толщины, но воспринимаются как единый блок.
- Строка статуса — показывает текущий шаг, процент выполнения и
  ожидаемое время (например: "Выполняется: Оптимизация диска C:  —
  40%  (ожидается ~1 мин)").
- Общий прогресс-бар — в процентах от общего числа запущенных шагов.
- Панель "Выполняемые пункты" — построчный список только тех пунктов,
  что были запущены, с иконкой статуса: ○ ожидание, ▶ выполняется,
  ✓ готово, ✗ ошибка, – отменено.
- Кнопка "Открыть отчёт" — становится активной после завершения, сразу
  открывает итоговый txt-файл.
- Кнопка "Бэкап" — открывает диалог точечного восстановления: можно
  выбрать, какие именно категории настроек (электропитание/брандмауэр/
  визуальные эффекты) восстановить, а не только всё сразу.
- Кнопка "Свернуть" — сворачивает окно в панель задач. Только вручную —
  программа не сворачивает и не разворачивает окно сама.

Вся работа (выполнение команд, удаление файлов) идёт в отдельном
фоновом потоке — окно не зависает и не превращается в "не отвечает"
даже во время долгих операций вроде sfc/scannow.

Список пунктов (см. раздел 3 ниже за подробным описанием каждого):
  1. Очистка временных файлов, логов и кэшей
  2. Очистка корзины
  3. Очистка диска (cleanmgr, без диалогов)
  4. Проверка системы: sfc /scannow + DISM RestoreHealth
  5. Оптимизация диска C: (TRIM для SSD / дефрагментация для HDD)
  6. Электропитание: схема "Высокая производительность"
  7. Визуальные эффекты: быстродействие (сглаживание шрифтов остаётся)
  8. Отключение брандмауэра во всех профилях
  9. Проверка скорости интернет-соединения

Информация о системе (CPU/RAM/диски/GPU/материнская плата/ОС) больше не
отдельный пункт выбора — собирается автоматически при каждом запуске и
всегда попадает в отчёт, независимо от отмеченных пунктов.

Тихая версия (system_cleaner_silent) выполняет первые 8 базовых шагов
(без визуальных эффектов и без проверки скорости интернета) — она
осталась в исходном наборе для запуска по расписанию.

Каждый пункт можно запустить как отдельно (кнопка рядом с ним), так
и в составе общего запуска (чекбокс + "Выполнить всё отмеченное").
При запуске одного пункта прогресс-бар и статус относятся только к нему.

Результат
---------
По завершении набора шагов в папке sclean на рабочем столе
(%USERPROFILE%\Desktop\sclean, создаётся автоматически при первом
запуске) создаётся файл:
  sclean_YYYY-MM-DD_HHMMSS.txt
(время в имени — чтобы несколько запусков за день не перезаписывали
друг друга). Отчёт — короткая сводка: сколько места освобождено на
диске C, скорость интернета (если пункт был отмечен) и информация
о системе (собирается всегда). Если какой-то из выбранных пунктов
завершился с ошибкой, в отчёте появляется раздел "Не удалось
выполнить" с причиной — если всё прошло успешно, этого раздела нет.
Старые отчёты автоматически удаляются, хранятся только последние
30 файлов.

Бэкап и восстановление настроек
---------------------------------
Перед выполнением шагов "Электропитание", "Отключить брандмауэр" и
"Визуальные эффекты" программа автоматически сохраняет текущее
состояние соответствующей настройки в файл sclean_backup.json внутри
той же папки sclean на рабочем столе (файл дополняется, а не
перезаписывается полностью — в нём накапливаются все три категории по
мере того, как запускались соответствующие шаги). Перед очисткой
Prefetch также сохраняется список имён удаляемых файлов (для справки —
сами файлы Windows пересоздаёт автоматически, восстановить их нельзя).

Кнопка "Бэкап" в окне открывает диалог, где можно выбрать, какие именно
категории восстанавливать:
  - Электропитание — возвращает активную схему на ту, что была до
    изменения;
  - Брандмауэр — возвращает состояние (вкл/выкл) по каждому профилю
    (Domain/Private/Public) отдельно;
  - Визуальные эффекты — возвращает значения реестра (VisualFXSetting,
    анимация окон, полное перетаскивание окон, сглаживание шрифтов).
Категории без данных в бэкапе показаны неактивными в диалоге.

Важно: это не восстанавливает удалённые файлы (TEMP, кэши, Prefetch
и т.д.) — такое удаление необратимо в принципе. Бэкап покрывает только
переключаемые системные настройки.

Сборка exe (на Windows, из этой папки):
  pyinstaller sclean.spec

(pystray/Pillow больше не требуются с версии 1.9.0 — сворачивание
работает через обычный root.iconify(), без сторонних зависимостей.
Никаких дополнительных pip install перед сборкой не нужно.)


================================================================
2. ТИХАЯ ВЕРСИЯ (system_cleaner_silent.py / system_cleaner_silent.exe)
================================================================

Работает без окна и без единого диалога (console=False), выполняет
ВСЕ 8 шагов подряд без возможности выбора и завершается сама. Полезна
для запуска по расписанию (планировщик заданий) без участия пользователя.

Сборка exe (на Windows, из этой папки):
  pyinstaller system_cleaner_silent.spec


================================================================
3. ЧТО ДЕЛАЕТ КАЖДЫЙ ШАГ (общее для обеих версий)
================================================================

1. Очистка временных файлов и системного мусора
   Очищаются (содержимое папок, сами папки не удаляются):
     - %TEMP% пользователя
     - C:\Users\<user>\AppData\Local\Temp
     - C:\Windows\Temp
     - C:\Windows\Logs\CBS
     - C:\Windows\Logs\DISM
     - C:\Windows\Prefetch — только файлы старше 24 часов (свежие не трогает)
     - C:\ProgramData\Microsoft\Windows\WER\ReportQueue
     - C:\ProgramData\Microsoft\Windows\WER\ReportArchive
     - Кэш миниатюр проводника (AppData\Local\Microsoft\Windows\Explorer)
     - Кэш обновлений Windows: C:\Windows\SoftwareDistribution\Download
       (служба wuauserv останавливается перед очисткой и запускается обратно)

   Файлы, занятые другими процессами, и защищённые системные объекты
   (desktop.ini, .lnk) пропускаются без падения программы — ошибки
   попадают в журнал, а не глушатся молча.

2. Очистка корзины
   Clear-RecycleBin через PowerShell (без подтверждения).

3. cleanmgr (профиль sagerun)
   Программа сама настраивает профиль очистки диска через реестр
   (эквивалент мастера /sageset, но без интерактивных шагов) — отмечает
   все доступные категории очистки — и запускает
   cleanmgr /sagerun:65432. В отличие от /verylowdisk, режим /sagerun
   не показывает диалог оценки места и не требует нажатия "ОК" по
   завершении — выполняется и закрывается сам.

4. Проверка целостности системы
   - sfc /scannow
   - DISM /Online /Cleanup-Image /RestoreHealth
   Может занимать 10–30+ минут. На свободное место напрямую не влияет.

5. Оптимизация диска C: (с автоопределением типа диска)
   Через Get-PhysicalDisk определяется SSD это или HDD:
     - SSD  -> только TRIM (defrag C: /L), полная дефрагментация НЕ
       делается (вредна для SSD — лишние циклы перезаписи)
     - HDD  -> полная дефрагментация (defrag C: /U /V)
     - Тип не определён -> безопасный режим по умолчанию (defrag C: /O)

6. Электропитание
   Активируется схема "Высокая производительность" (стандартный GUID
   Windows). Если схемы нет в списке — создаётся из встроенного шаблона.

7. Визуальные эффекты: быстродействие (только GUI-версия)
   Через реестр (HKCU) переключает визуальные эффекты Windows в режим
   "Обеспечить наилучшее быстродействие" (VisualFXSetting=2): отключает
   анимации окон, тени, прозрачность и т.п. При этом ОТДЕЛЬНО оставляет
   включённым сглаживание экранных шрифтов (ClearType/FontSmoothing),
   которое этот режим по умолчанию тоже отключил бы — читаемость текста
   не страдает. Изменения применяются после перезахода в систему или
   перезапуска explorer.exe.

8. Брандмауэр Windows
   Отключается во ВСЕХ профилях (Domain, Private, Public):
     netsh advfirewall set allprofiles state off
   Внимание: это снижает защиту системы. Включить обратно:
     netsh advfirewall set allprofiles state on
   либо через "Брандмауэр Защитника Windows" в панели управления.

9. Проверка скорости интернет-соединения (только GUI-версия)
   Основной способ: официальный Ookla Speedtest CLI (speedtest.exe),
   запускается без окна в фоне и выдаёт JSON с реальными данными —
   провайдер, сервер, скачивание, отдача, пинг (те же данные, что
   показывает speedtest.net). Программа ищет speedtest.exe в такой
   последовательности: рядом с sclean.exe/sclean.py, затем в PATH.
   Если нигде не найден — используется резервный способ: скачивание
   тестового файла с Cloudflare/Hetzner по HTTPS и расчёт скорости
   скачивания (без пинга и отдачи).

   Чтобы получить полноценные данные, скачайте speedtest.exe с
   официального сайта Ookla (https://www.speedtest.net/apps/cli) и
   положите файл рядом с sclean.exe (или добавьте в PATH). Первый
   запуск CLI требует принятия лицензии — программа передаёт флаги
   --accept-license --accept-gdpr автоматически, отдельного действия
   от пользователя не требуется.

   Результат попадает в журнал и в отдельный блок отчёта
   "[Скорость интернет-соединения]". Если ни CLI, ни резервный способ
   не сработали — в отчёте фиксируется, что измерить не удалось
   (программа не падает).

Сбор информации о системе (выполняется автоматически при каждом
запуске GUI-версии, не является отдельным пунктом выбора)
   Через PowerShell/CIM собираются:
     - Процессор: модель, физические ядра, логические потоки
     - ОЗУ: общий объём, количество модулей, частота, код типа памяти
     - Диски: модель и объём каждого физического диска, список разделов
       (буква, общий объём, свободно, файловая система), тип диска C
       (SSD/HDD)
     - Видеокарта(ы): название, объём видеопамяти (VRAM), пометка
       встроенная/дискретная (по модели — Intel/встроенный AMD Radeon
       Graphics считаются встроенными, NVIDIA GeForce/RTX/GTX и
       отдельные AMD Radeon RX — дискретными)
     - Материнская плата: производитель и модель
     - Устройство: имя компьютера в сети
     - ОС: полное название (выпуск), версия функциональности (например
       25H2), дата установки, полный номер сборки в формате build.UBR
       (тот же формат, что показывает "Параметры -> Система -> О системе")


================================================================
4. ВАЖНЫЕ ПРЕДУПРЕЖДЕНИЯ
================================================================
- Обе версии отключают брандмауэр Windows во всех профилях — это
  осознанное снижение защиты системы, включайте обратно вручную при
  необходимости.
- GUI-версия (sclean) всегда запускается с правами администратора —
  без подтверждения UAC не откроется.
- Работают только на Windows.
- sfc/DISM могут занимать значительное время — в GUI-версии это видно
  по статусу текущего шага, но кнопки заблокированы до завершения фоновой
  операции.
- Шаг "Очистка диска" использует режим cleanmgr /sagerun — в отличие
  от /verylowdisk, он не показывает диалог оценки места и не требует
  нажатия "ОК" по завершении. В отличие от остальных шагов, этому окну
  разрешено ненадолго появиться на экране (обычно на несколько минут,
  зависит от объёма данных) — это сделано намеренно: полностью скрытый
  GUI-процесс иногда зависает, ожидая взаимодействия с окном, которое
  никогда не отрисуется. Пока идёт этот шаг, окно sclean может выглядеть
  неактивным — это ожидаемо, дождитесь завершения cleanmgr.

  dist\system_cleaner_silent.exe   — собранный exe тихой версии (после сборки)

Файл sclean_backup.json (в папке sclean на рабочем столе) создаётся
программой автоматически при первом выполнении шагов электропитания/
брандмауэра/визуальных эффектов — в проекте его нет, в .gitignore/
поставку включать не нужно.

Примечание: sclean.ico и sclean_logo.png должны лежать рядом с sclean.py
при запуске как скрипт, либо быть встроены в exe через datas в .spec
(уже настроено) — при сборке через pyinstaller sclean.spec ничего
дополнительно копировать не нужно.
